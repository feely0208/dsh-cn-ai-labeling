# AI 生成内容标识检查（dsh-ai-labeling）

**什么时候用**：项目里接了 OpenAI / Anthropic / DeepSeek 等模型接口，要确认「AI 生成的东西标了没」。
用户会说：「AI 标识」「AI 生成内容标识」「显式标识」「隐式标识」「深度合成标识」「AIGC 要不要标注」
「生成的内容有没有提示用户」「内容标识合规」。

## 怎么用

```bash
dsh-ai-labeling --root <项目目录>     # 扫一个项目
dsh-ai-labeling --demo                # 看内置样本的检出效果
dsh-ai-labeling --list-rules          # 列规则与依据
```

## 它查什么（5 条）

| 规则 | 查什么 | 级别 |
|---|---|---|
| `AILABEL-NO-DISCLOSURE` | 生成结果被直接回给用户的文件里，没有「AI 生成」显式标识 | 高 |
| `AILABEL-MISSING-TEXT` | 全项目一句「AI 生成 / 由 AI 生成 / AI-generated」标识文案都没有 | 高 |
| `AILABEL-NO-REVIEW` | 面向用户的输出没有「人工核验 / 仅供参考」提示 | 中 |
| `AILABEL-NO-IMPLICIT-META` | 生成产出文件里没有 `generated_by` / `ai_generated` 等隐式标识字段 | 中 |
| `AILABEL-VAGUE-GENERATED` | 用户可见文案写「自动生成 / 系统生成」，没有 AI 字样 | 低 |

**所有规则都带 `when` 守卫**：项目里没有模型 SDK / 生成调用时，规则判定为「不适用」而不是「通过」——
报告里会写「5 条因不适用本项目未运行」。不用 AI 的项目不会被骚扰。

## 怎么读结果

1. **谁的话，说清楚**（`NO-DISCLOSURE` / `MISSING-TEXT`）—— 加显式标识。标识要出现在**用户实际看到的那份内容**上，写在 README、注释、后台日志里不算。
2. **能不能直接采信**（`NO-REVIEW`）—— 加「仅供参考，请人工核验」。AI 是概率输出，会有事实性错误。
3. **搬运之后还认得出吗**（`NO-IMPLICIT-META`）—— 隐式标识是给机器看的元数据（`generated_by` / `ai_generated` / `model_name` / `service_provider` / `content_id`），作用是内容被二次分发后仍可追溯。
4. **别用糊涂词**（`VAGUE-GENERATED`）—— 「自动生成」「系统生成」看不出背后是模型，要写「AI 生成」。反过来说，也**不要**写成「作者」「编辑」这类像自然人的身份来规避标识。

## 不要做什么

- 不要把它当「内容是不是 AI 生成的」判断器 —— 那要运行时，静态看不出来。它只查**调用了模型却没说**。
- 不要把它当事实核查 —— 它看的是「有没有提示可能存在错误」，不是「这句话对不对」（那是另一条赛道）。
- 不要把命中当成「违法」—— 命中是**提示确认**：这里可能缺标识，请你判断。它不下「合规 / 不合规」的结论。
- 不要为了消警把标识文案写进注释或后台日志 —— 那不是给用户看的标识。

## 依据

- 《生成式人工智能服务管理暂行办法》第 12 条（对生成内容进行标识）
- 《互联网信息服务深度合成管理规定》第 17 条（深度合成内容标识）
- 《人工智能生成合成内容标识办法》第 4 条（显式标识）、第 5 条（隐式标识）
